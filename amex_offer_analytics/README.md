# Offer Redemption & Customer Segmentation Analysis

An end-to-end analytics project modeled on how a card-linked offers platform
(like Amex Offers) analyzes customer offer redemption behaviour using Python, SQL, RFM analysis, K-Means clustering, and Power BI.

The project simulates a card-linked offers platform and focuses on understanding offer performance, customer segments, redemption trends, and revenue contribution.

**What it does:**
1. Generates a realistic offers dataset (customers, merchants, offers, redemptions)
2. Runs SQL analysis on adoption rate, category performance, and top offers
3. Segments customers with RFM + K-Means clustering
4. Produces charts and Power-BI-ready CSVs
5. Built an interactive Power BI dashboard to visualize the key findings

---

## 1. Project Files


### Step 1 — `01_generate_data.py`: the dataset
Generates four linked tables:

| Table | Rows | What it represents |
|---|---|---|
| `customers.csv` | 5,000 | Card member demographics (age, income bracket, tenure, card type) |
| `merchants.csv` | 150 | Merchants across 8 categories (Dining, Travel, Grocery, etc.) |
| `offers.csv` | 600 | Offers each merchant ran (discount %, min spend, offer type, dates) |
| `offer_exposures.csv` | 60,000 | The fact table — a customer was shown an offer, and either redeemed it or didn't |

**Why synthetic data :** Amex doesn't publish real
Offers data publicly, and the closest real-world Kaggle dataset
("Predicting Coupon Redemption," originally an AmExpert hackathon case
study) doesn't include merchant-category or spend detail. So this generator
builds redemption behavior from an actual probability model, a customer's
engagement level, the category's natural appeal, the discount size, and the
minimum spend barrier all combine (via a logistic function) to determine
redemption likelihood. That's *why* the category and segment patterns you'll
see are real, explainable signal and not random noise.


### Step 2 — `02_load_to_sql.py`: SQLite database
Loads the four CSVs into a local `amex_offers.db` file using `sqlite3`
no database server install needed.

### Step 3 — `03_sql_analysis.py`: SQL analysis
Runs 7 queries covering exactly the metrics the JD asks for:
- Overall offer adoption rate
- Redemption rate & revenue by merchant category
- Top 10 performing offers
- Redemption rate by discount tier (does a bigger discount actually work?)
- Redemption rate by income bracket & card type
- Customer redemption frequency distribution
- Monthly redemption trend


### Step 4 — `04_rfm_segmentation.py`: customer segmentation
Performs customer segmentation using:
- **Recency** — days since their last redemption
- **Frequency** — how many offers they've redeemed
- **Monetary** — total spend on redeemed offers

Then it standardizes these and runs **K-Means clustering (k=4)**, and labels
each cluster by its actual centroid behavior — not arbitrary names:

| Segment | Typical profile |
|---|---|
| Champions | Frequent, recent, high-spend redeemers |
| Steady Redeemers | Moderate frequency and spend |
| At-Risk / Lapsing | Used to redeem, haven't recently |
| Low-Engagement / New | Never redeemed |


### Step 5 — `05_visualize.py`: charts
Produces four PNGs  redemption rate by category,
segment distribution, an RFM scatter plot, and revenue by segment.

## 2. Power BI Dashboard
The outputs generated by the Python and SQL pipeline are used to build an **interactive Power BI dashboard**.

The dashboard includes:

- **KPI Cards** — overall adoption rate, redeemed revenue, and number of Champions
- **Clustered Bar Chart** — redemption rate by merchant category
- **Donut Chart** — customer distribution by segment
- **Line Chart** — monthly redemption trend
- **Interactive Slicer** — filter analysis by category/segment
